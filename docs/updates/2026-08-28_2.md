# MadaIwakiのSIGKILL時データ欠落を修正

## 背景

`scripts/mada.py`の`run_period()`は、有効化された複数ボードのうち最初にevent_numへ到達した1台が終了した時点で、`kill_gigaiwaki_processes()`により残りの全MadaIwakiプロセスへ`SIGKILL`(signal 9)を送る設計になっている(`ProgressMonitor.wait_for_any_exit()`)。

一方`source/MadaIwaki.cc`側は`OutData.write(c_data, num)`のみを行い、`flush()`/`close()`は`trig_count >= max_trig`に達した正常終了パスでしか呼んでいなかった。`std::ofstream`は内部にバッファを持つため、SIGKILLされるとデストラクタが走らず、まだOSに渡っていないバッファ内のデータがそのまま失われる。

このため、複数ボード運用時に最初に終わったボード以外は、毎ファイル受信済みデータの末尾を欠落させていた可能性がある。

## 変更内容

- `source/MadaIwaki.cc`: `OutData.write()`の直後に`OutData.flush()`を追加。`flush()`はカーネルへの書き込み(write(2)相当)を即座に行うため、SIGKILLされても既読分のデータは保持される(まだOSの受信バッファに残っている未読データは対象外)。
- `bin/MadaIwaki`を再ビルド・再インストール済み。

## 保留事項

- counter-resetパルス(`mada_adalm_control.py`経由、ファイル毎に発行)の配線がファームウェアの`CntReset`に対応しているかは実機未検証([docs/manuals/2026-08-24.md](../manuals/2026-08-24.md)参照)。今回の調査でユーザーからファイル毎リセットは意図通りとの回答を得たため、本修正では変更していない。
