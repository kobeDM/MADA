# 2026-11-08 読み出し失敗時のファイルやり直しと警告の見直し

## 背景

per0007 (GBKB-32)、per0008 (GBKB-31)、per0012 (GBKB-31) で、新しいファイルの開始直後に
1枚のボードの MadaIwaki が recv 失敗で終了し、DAQ 全体が停止した。失敗したボードのファイルは
0 B、他のボードは数十イベントだった。

## 変更

- 読み出し失敗 (リーダの異常終了) のファイルは、消さずに無効として残し、全ボードで次のファイル番号からやり直す。
  - カウンタリセットは全ボード共通のパルスなので、1枚だけのやり直しはしない。
  - `mada_progress.py` は `ReaderExitError` (GigaIwakiError の派生) を送出する。`mada_file_cycle.py` の `run_file` が捕まえ、DAQ enable を下げて通常どおり finalize し、False を返す。
  - 無効ファイルにも番号を振り (欠番にしない)、ピリオドの `file_num` には数えない。
  - 無効が `MAX_INVALID_IN_ROW` (3) 回連続したら、従来どおり DAQ を停止する。
  - 起動時の失敗 (start_readers) や、読み出し以外のエラーは従来どおり停止する。
- 無効の記録
  - `warnings.log`: `WARNING t=... kind=file_invalid boards=GBKB-31 reason="..."` (source は DAQ)。
  - 各ボードの `.info` の `runinfo` に `"valid": false` と `"invalid_reason"`。キーがなければ有効。
- MadaIwaki
  - `recv_wait` の警告を廃止した (大きなイベントのボードでトリガ間隔の揺らぎが警告になっていた)。`write_slow` と summary は維持。
  - recv 失敗のメッセージに errno と strerror を追加した。
- ボード間の遅れ検出 (`board_lag`) を ProgressMonitor に追加した (T = 0.2 s)。
  - 他のボードが持つイベントを、あるボードが 0.2 s 以上持たないとき `WARNING kind=board_lag events lead sec`、解消時に `INFO kind=board_lag_end`。
  - ポーリング間隔 (0.2 s) と T が等しいため、1〜2イベントの短い遅れでも警告が出る (誤警告)。現状は容認。

## 解析での扱い

`.info` の `valid` が false のファイルは除外する。そのファイルの他ボードのデータは、調査用に残してある。
