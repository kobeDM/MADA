# LVリセット監視の常駐化と veto の持ち主の一本化

## 背景
- LVリセット監視 (`RegulatorAutoresetMonitor`) が `mada.py` の中のスレッドだったため、`mada_encoder_power.py` などで直接APを入れた場合は保護が働かなかった。

## 変更
- `mada_regulator_autoreset.py` を常駐プロセスとして使う: `-d` でバックグラウンド起動 (ログ `run/mada_autoreset.log`、PID `run/mada_autoreset.pid`)、`--stop` で停止。二重起動は拒否する。
- `mada.py` は監視を起動・停止しない。起動していなければ警告を出す。
- veto (ADALM D12) は監視プロセスだけが操作する。起動時と終了時にLOWにする。
  - release 失敗時は10秒間隔で再試行し、`run/veto.state` に failed を記録する。`mada.py` はファイル境界でこれを確認し、failed なら安全停止する。
  - ログは `run/veto.log` に移動 (絶対パス)。
- AP が OFF の基板は、リセット (と veto) の対象から外す。AP状態は基板のレジスタ 0xf1 を `ReadCtrlMem IP 0xf0 0x10` で読む (`ReadCtrlMem` にアドレス範囲指定を追加)。読み出せない場合はONとみなしてリセットする。
- AP操作が失敗しても監視スレッドは止まらない。AP on は3回まで再試行し、それでも失敗したら基板がOFFのままであることをログに出す。

## 検証 (実機のADALM、基板操作はモック。基板が応答しなかったため)
- 疑似の過電流行で、D12 が HIGH になり、最後のAP on の約0.5秒後にLOWへ戻る。
- AP OFF の基板では何もしない。
- release を2回失敗させると、failed が記録され、再試行で成功すると解除・failed が消える。
- AP操作が全て例外になっても、監視スレッドは生存し、veto は解除される。
- 常駐の起動、二重起動の拒否、`--stop` (D12 LOW、PIDファイル削除) を確認した。
- 未確認: 実機の基板での AP 状態の読み出し (0xf1)、DAQ実行中のファイル切替と veto の競合。

## 運用上の注意
- 監視は設定を起動時に1回だけ読む。基板やモジュールが変わるときは再起動する。
- SIGKILL で落とすと D12 がHIGHのまま残りうる。再起動で LOW に戻る。
