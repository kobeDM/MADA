# DAQ フローの整理 (1ファイル1機能、エラー処理の追加)

ブランチ `refactor-daq-flow`。使い方(コマンド名、オプション)は変えていない。

## 構成
- 設定の読み込みを `mada_config.py` に集約(従来は15ファイルが各自で `json.load`、`get_active_boards` などが重複)。ADALM の役割とマスクは `mada_adalm_roles.py`。
- `mada.py` (406行) を分割: 入口 (`mada.py`)、セッション (`mada_daq_session.py`)、1ファイル (`mada_file_cycle.py`)、読み出し (`mada_gigaiwaki.py`)、進捗 (`mada_progress.py`)、ログ (`mada_run_logger.py`)。
- `mada_daq_killer.py` の `.info` 更新を、`RunLogger.finalize_file` に統合(従来は二重実装)。
- ADALM の実行を `mada_adalm_runner.py` に、CLI を `mada_adalm_control.py` に分離。
- プロセスの停止を `mada_process.py` に集約(3か所の別実装を統合)。
- 常駐監視を、起動保証 (`mada_autoreset_ctl.py`)、ロジック (`mada_regulator_monitor.py`)、コマンドライン (`mada_regulator_autoreset.py`)、AP 状態 (`mada_ap_state.py`) に分離。
- `mada_errors.py`: すべての停止エラーの基底 `MadaError`。
- 削除: 重複した `load_config`、`get_active_boards`、`run_kill_daq`、`update_latest_info`、`daemonize` と `detach` の重複実装、未使用の `bg` 引数、未使用の import。

## 動作の変更
- **読み出しの再起動**: MadaIwaki が起動中に異常終了(接続の拒否・切断)した基板だけを、最大3回再起動する。counter reset と DAQ enable は、全員が起動してから、全ボード分を1回のコマンドで送る(個別送信はしない)。取得中に落ちた場合は従来どおり停止する。
- **毎ファイルの `run_kill_adalms` をやめた**: DAQ 開始時の1回だけにした(監視プロセスの veto 操作中の AdalmControl を止める恐れがあったため)。
- **`--calin` を電源投入に渡す**: 従来は指定しても SetAllDAC に渡っていなかった。
- **`mada_daq_killer`** が `-c` の設定を使う(従来は常に `MADA_config.json`)。終了済みのファイルの end を上書きしない。

## エラー処理の追加
- 設定の検証(必須項目、DACファイルの存在、ADALM の役割とマスクの重複)を、デーモン化の前に行い、不備は理由つきで停止する(従来は `KeyError` など)。
- ADALM: ロック待ち60秒、1回の呼び出し20秒のタイムアウト(固まった AdalmControl がロックを持ち続けるのを防ぐ)。タイムアウト時は kill してリトライ。
- プロセス停止: プログラム名で完全一致(コマンドラインに名前を含むだけのシェル等は対象外)。SIGTERM の後に待ち、残れば SIGKILL。
- 終了処理(最後のファイルの終了、読み出しの停止、DAQ enable の latch down、電源断)を個別に保護し、先に起きたエラーを隠さない。電源投入の途中で失敗した場合も AP を OFF に戻す。想定外の例外はトレースバックを出して終了処理を実行する。
- `.info` の欠落、`.mada` の欠落、レートログの保存先の欠落、所要時間0、`mada_stop_daq.py` の壊れた PID ファイル。
- MadaIwaki の標準エラーを、基板名を付けて出力する(以前は端末にしか出ず、デーモン時に追えなかった)。

## 検証 (基板・ADALM に触れない、偽のバイナリでの通し)
- 正常: 3基板で、読み出しを同時に起動 → 1秒待ち → counter reset → DAQ enable の順。終了検知の直後に latch down。
- 1基板の読み出しが起動中に2回失敗: その基板だけ再起動し、counter reset と DAQ enable は1回ずつ。
- 読み出しが起動できない / 取得中に落ちる / ADALM が常に失敗 / 設定の不備 / SetAllDAC の失敗: いずれも後始末(latch down、AP OFF、`.info` の終了処理)をして終了コード1。
- 各モジュールの単体試験(設定、役割の検査、プロセス停止、ADALM ランナーのリトライ・タイムアウト・ロック待ち、ログ、レートログ、監視のロジック、デーモン、停止スクリプト)。
- 未確認: 実機の基板・ADALM での通し(基板が電源オフだったため)。
