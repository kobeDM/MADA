# DAC/Vth スキャンの自動化と精度向上 (mada_scan.py)

## 背景
- 従来のスキャン(`mada_run_vth_scan.py`、`mada_run_dac_scan.py`)は、ボードごとに手で実行し、結果の DAC ファイルも手で整える必要があった。
- 解析に次の問題があった。
  - ヒット率の分母に、ヒットデータのないイベント(20 バイトの空イベント)を含めておらず、しきい値の高い側でヒット率が過大になる(`Vth_run0097` の 1 点で、実際は 2.5% のところ、99% 以上)。
  - Vth スキャンの中心は、「ヒット率が 0.5 に最も近い点」で、刻み(32 や 100)がそのまま誤差になる。
  - DAC の補正は、1 DAC あたり Vth 52 カウントという仮定の定数に頼っている。
  - データが来ないと、いつまでも待ち続ける(`DACSurvey` には時間制限がない)。
  - ヒット固着・ヒットなしのチャンネルを区別せず、フィットや平均に混ぜる。

## 変更
- 新しい実行ファイル(`source/`、`bin/`)
  - `ScanAcquire`: 1 ボードで、Vth または DAC を順に設定し、1 点あたり `-n` イベント(既定 500)か `-t` 秒(既定 15)のどちらか早いほうまで取る。タイムアウトした点は、取れた分を保存して記録する。全点でイベントが 0 のときはエラー(コード 3)で止まる。
  - `ScanFit`: チャンネルごとに、ヒット率を erf でフィットし、中心(50% の点)と幅を求める。dead(常にヒットなし)、stuck(常にヒット)、no_transition、fit_failed、insufficient は、フィットせずに分類する。`fit_result.csv/.root` と `fit_summary.png` を出す。旧 `ScanVth`/`DACSurvey` のデータも読める。
  - `ScanCorrect`: `dac`(DAC スキャンから DAC ファイル。フィットできないチャンネルは、参照ファイルの値)、`slope`(2 つの DAC スキャンから Vth カウント/DAC の実測)、`refine`(Vth スキャンの中心を目標に合わせる)。補正の不感帯は 0.6 DAC。
- Python(`scripts/`): `mada_scan.py`(入口)、`mada_scan_session.py`(DAQ enable、全ボードの並列実行、ボードの設定の復元、まとめ)、`mada_scan_board.py`(1 ボードの流れ)、`mada_scan_tools.py`(バイナリの呼び出し)。
- 流れ: DAC スキャン(作業点の Vth)→ 2 点目の DAC スキャン(傾きの実測)→ Vth スキャンで確認し、補正して再スキャン(変化がなくなるか、`--max-iter` まで)。
- `ScanFit` が、旧 `Vthcheck.png` と同じ形式の図(縦軸が Vth か DAC の値、目標の Vth の赤線)を、`vth_scan_N/Vthcheck.png`、`dac_scan_N/DACcheck.png` に出す。`mada_scan_replot.py` で、保存済みのスキャンの図とフィットを、ボードに触れずに作り直せる。
- `SiTCP` に、時間制限つきの読み込み(`ReadTimeout`)を追加した。

## 揃える位置を、ノイズ率の低い点にする(`--level`)
- 当初は、ヒット率が 50% になる点(ノイズの遷移の中央)に、チャンネルを揃えていた。ノイズだけの測定で 50% は、ノイズが常時ヒットしている点なので、揃える位置として適切でない。
- `ScanFit` に `level` を追加した。ノイズのヒットがない側から見て、遷移全体(ヒット率が一定の高い側と、ヒットのない側の差)の `level` の割合まで、ヒット率が上がった点を、`aligned` として `fit_result.csv` に出す。`ScanCorrect` は、`aligned` の列を使う(`level` = 0.5 は、フィットの中心)。
- 低いレベルの位置は、erf の外挿ではなく、データの内挿で求める。ノイズ分布の裾が、erf より重く、`GBKB-34` の実データで、erf の外挿は、データの位置から 50〜100 カウントずれた。
- ノイズのヒット率 1% でも、1 イベントの 1024 クロックのうち約 10 クロックにヒットがあるので、ほぼ全イベントで、そのチャンネルにヒットが立つ(`scan_run0003` の作業点で、イベント占有率 0.8〜1.0)。ノイズだけの測定でヒットがないようにするため、揃える位置の基準に、イベント占有率(ヒットが 1 クロックでもあったイベントの割合)を追加した(`--metric occupancy`、`ScanFit` の 5 番目の引数)。
- `mada_scan.py` の既定は `--metric occupancy --level 0.005`(DAC スキャンは `--dac-level 0.05`)。尾の統計のため、Vth スキャンだけ、`--vth-events` で、1 点あたりのイベント数を増やせる。
- 占有率で揃える場合、クロックのヒット率の erf フィットは使わない(フィットの成否で、ノイズの多いチャンネルや、遷移が範囲の端にあるチャンネルが脱落していた)。分類は、占有率の推移で行い、揃える位置は、データの内挿で求める。
- Vth スキャンの範囲は、DAC スキャンから判定したヒットのある側(カソード: 低い Vth、アノード: 高い Vth)へ `--window-hit`(既定 300)、反対側へ `--window-nohit`(既定 300)とした。補正は最大 `--max-iter`(既定 5)回。
- ボードごとの進捗バー(段階、完了した点数、経過時間、残り時間の目安)を表示する(`mada_scan_progress.py`)。端末ではその場で書き換え、ログファイルでは 1 分ごとに 1 行出す。
- 占有率の中央値が 5% と 1% になる Vth(`scan_run0003` の保存データによる見積もり。作業点からの差): GBKB-34 は +77 と +100、GBKB-35 は +98 と +120、GBKB-32 は −74 と −107、GBKB-33 は −90 と −115(アノードは、Vth を下げるとヒットが減る)。チャンネルごとの縁(ヒットが最後に出る Vth)の rms は、25〜56 カウントで、DAC の補正をしても、縁は揃っていない。
- `mada_scan_replot.py --level L` で、保存済みのスキャンを、別のレベルで解析し直せる。

## 検証
- 過去のスキャンデータ(`/nadb61/dacScan`)で `ScanFit` を実行した。DAC スキャンは、旧 `base_correct.dac` と整数に丸めた値が一致した。Vth スキャンは、旧解析の `center` との差の rms が、刻みによる量子化(100 カウントの刻みで約 30)と同程度だった。旧解析の中心が外れていた例もあった(Vth_run0100 で最大 2780 カウント)。
- 実機(4 ボード)で、`config` の Vth を各ボードのノイズの縁に置き、`-n 300 --vth-events 2000` でスキャンした(25 分)。最後の Vth スキャンで、全ボードの揃えた位置の中央値が、作業点の ±5 カウント以内、rms が 12〜16 カウント(DAC の分解能の限界とほぼ同じ)になった。フィットされなかったのは、元から壊れている 3 チャンネル(GBKB-33 の ch54 が dead、GBKB-35 の ch12 と ch14 が stuck)だけだった。
- ボードを模したモックで、全体を通した。真の σ(25)と傾き(52 Vth/DAC)を再現し、dead 2 ch と stuck 1 ch をフィットから除外した。補正後の中心の rms は、DAC の量子化の限界(約 15 カウント)に収まり、2 回目の確認で変化がなくなった。実機での確認はこれからである。

## 注意
- DAQ が走っていないこと、外部トリガーの供給が前提である。レギュレータ(AP)が OFF のボードは、スキャンの開始時に自動で ON にし(LV リセットの監視も起動する。`config` の Vth、DAC、bias も書き込む)、終了時に OFF に戻す。すでに ON のボードは、ON のままにする。ボード自体の電源(基板の電源)は、入っている必要がある。
- ノイズだけを使うので、ノイズの少ないチャンネルや、Vth の掃引範囲内でヒット率が変化しないチャンネルは、フィットされない。
- 補正後の DAC ファイルは、`scan_runNNNN/<ボード名>.dac` に出力する。`config` への反映は手動である。
- 旧スクリプトは、残してある(`mada_run_*_scan.py` など)。
