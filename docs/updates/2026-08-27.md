# ボードセットアップがperiodごとに再実行される不具合を修正

## 背景

`mada.py`の`run_daq()`(旧実装)は`main()`の`while True`ループから**period単位で**呼ばれており、`run_kill_modules()`・`run_encoder_power_up()`(レギュレータAP ON→ADCバイアス→DAC/Vth→latch-up検出ON)を関数冒頭で、`run_encoder_power_down()`を末尾で実行していた。想定は「ボードセットアップはDAQ開始時のみ」だが、実際には`file_num`ファイル撃ち終えて新periodに移るたびにレギュレータOFF→ON・DAC/Vth再設定・latch-up検出の再有効化が発生していた。

## 変更内容

- `scripts/mada.py`: セットアップ/ティアダウン(`run_kill_modules`、`run_encoder_power_up`/`run_encoder_power_down`、`RegulatorAutoresetMonitor`の起動/停止、ADALMシリアル番号の取得)をperiodループの外側に出し、DAQセッション全体で1回のみ実行されるようにした。
  - period/fileループの本体を`run_period()`として分離し、`run_daq()`はセットアップ→`while True`でperiod生成+`run_period()`呼び出し→(Ctrl+C時)`run_daq_killer()`→`finally`でティアダウン、という構成に変更。
  - `main()`側の`while True`(period生成ループ)は`run_daq()`に統合したため削除。
- `README.md`の「Start DAQ」節の説明を、セットアップが起動時1回のみである実際の挙動に合わせて修正。
