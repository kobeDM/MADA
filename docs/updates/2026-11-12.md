# スケーラー(runScaler)のDAQへの組み込み

## 背景
スケーラーはZYBO(`msgc@10.37.0.241`)上の `runScaler`(MAZYSCA_SW)で、DAQと同時に動かす。これまでは手動で、periodごとに
`runScaler <出力ディレクトリ> <period番号>` を起動し、DAQ停止後に止めていた。

## runScaler の仕様(ソース `MAZYSCA_SW/src/runScaler.cc` から)
- 1回の起動は1periodを担当し、 `<出力ディレクトリ>/perNNNN` に書く。同名のファイルがあると上書きする。
- DAQ enable の立ち下がりごとに1行(ファイル番号、リアルタイム、ライブタイム、トリガー数、時刻)を書く。ファイル番号は0から。
- 起動後の最初の1回は読み捨てる(待機状態の吸収)。したがって、DAQ enable が下がっている間(ファイルの間)に起動する必要がある。
- シグナルの処理はなく、SIGTERM で止める。GPIOの失敗では `abort` する。
- 出力ディレクトリはDAQ PCの `/nadb61/scaler/<run名>` と同じ場所(共有)。ただしZYBOではDAQ PC(10.37.0.244)の `/nadb61` がNFSで
  `/nadb/nadb61` にマウントされているので、ZYBOから見たパスは `/nadb/nadb61/scaler/<run名>` である(設定 `SCALER.remote_output_root`)。

## 方針
periodごとに起動し直す必要があり、periodの境界は `mada.py` が決めるので、制御は `mada.py` に組み込む(クライアント/サーバーは状態の表示のみ)。

## 動作
1. 起動前(デーモン化の前): `SCALER` セクションの検証と、sshで接続とコマンドの実行権を確認する。失敗すれば `Error:` で終了。
2. セッション開始(電源投入の後): 前回の `runScaler` が残っていれば停止する(`pkill -x runScaler`)。
3. periodの開始(最初のファイルの前、DAQ enable は低): `runScaler <remote_output_root>/<run名> <period>` をリモートで起動し、出力ファイルの生成を確認する。
   既にファイルがあれば起動せずにエラー。
4. 各ファイルの後: 出力の行数がファイル数と一致するか確認する(DAQ enable の立ち下がりは無効ファイルでも起きるので数える)。
   一致しなければ(最大3秒待つ)エラー。
5. periodの終了: 停止する(2回まで試す)。止められなければエラー。
6. 終了処理: DAQ enable を下げ、スケーラーが最後の立ち下がりを記録するのを待ち(0.5秒)、基板の電源を切ってからスケーラーを止める。
   停止の失敗は警告のみ(電源OFFを優先)。

スケーラーの起動失敗、記録漏れ、停止失敗はDAQを止める(ライブタイムが失われるため)。

## 追加・変更
- `scripts/mada_scaler.py`(新規): `ScalerRunner`(`preflight`、 `clean_stale`、 `start`、 `verify_file`、 `stop`)。状態は `run/mada_scaler.json`。
- `scripts/mada_config.py`: `scaler_settings`、 `validate_scaler`。
- `scripts/mada_file_cycle.py`(`run_period`)、 `scripts/mada_daq_session.py`、 `scripts/mada.py`: 上記の組み込み。
- `config/MADA_config_SKEL.json`: `SCALER` セクション(既定は `active: 0`)。
- クライアント: `/status` の `monitor.scaler`(API契約と各仕様書を更新)。シミュレータも状態ファイルを書く。
- 試験: `tests/test_scaler.py`(偽の `ssh` と `runScaler` を使用)。

## 実機確認の結果(2026-11-12、ZYBO mazysca01)
`ScalerRunner` を直接呼び、試験用の出力先 `/nadb61/mada_scaler_test`(ZYBOから `/nadb/nadb61/mada_scaler_test`)で確認した。
ADALMとDAQ enable には触れていない。

- 鍵認証での接続、 `runScaler` の実行権の確認(`preflight`)、残留の停止(`clean_stale`、 `pkill -x runScaler`): 成功。
- 起動: 0.6秒。ZYBO上で `runScaler /nadb/nadb61/mada_scaler_test/trial 9999` が動き、DAQ PC側に `per9999`(空)が生成された。
- 停止: 0.6秒。ZYBO上にプロセスが残らず、状態ファイルは `stopped`。
- 既存の `per9999` がある状態での再起動: 上書きを拒否してエラー。
- 未確認: DAQ enable の立ち下がりに対する行の記録(ファイル番号0が最初のファイルに対応するか)。DAQ enable を実際に動かす必要がある。

## 実機での確認事項
- (済) sshの鍵(`/home/msgc/.ssh/id_ecdsa`)をZYBOに登録し、host key を登録した。
- 2つ目以降のperiodで、スケーラーのファイル番号0が最初のファイルに対応していること(ファイルの間に起動したときの読み捨てが想定どおりか)を確認する。
  食い違えば、各ファイルの後の行数確認で検出されてDAQが止まる。
- ZYBO側の `/tmp/mada_runScaler.log` に `runScaler` の標準出力・エラー出力が残る。
