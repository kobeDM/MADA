# mada.pyにバックグラウンド実行機能を追加

## 背景

従来`mada.py`は端末にアタッチしたフォアグラウンド実行のみで、SSHセッションを閉じるとDAQが止まってしまっていた。端末から切り離してバックグラウンドで実行し続けたいという要望に対応する。

## 変更内容

- `scripts/mada_daemon.py`を新規追加(mada.py専用のimportモジュール、単体実行は想定しない)。ログ・PIDファイルのパスは`$MADAHOME/run/`配下に固定し(オプションでの変更は不可)、`mada.py`・`mada_stop_daq.py`の両方がこのモジュールの定数/関数を参照することでパスのずれが起きないようにした。`run/`は`config/DAClog`と同様のランタイム生成ディレクトリとして`.gitignore`に追加。
  - ログファイルは1period=1ファイルとし、`log_path(period)`が`<run_name()>_<period:04d>.log`(例: `20260817_0007.log`)を返す。`run_name()`は起動ディレクトリ名(`os.path.basename(os.getcwd())`、通常は日付名のデータディレクトリ)。period番号は`RunLogger.new_period()`が起動ディレクトリ内で単調増加させ再利用しないため、同日に複数回runを行っても、また1回のrunが複数periodにまたがっても、ファイル名が重複することはない。
  - `daemonize(first_period)`: `RUN_DIR`を作成した上で`os.fork()`により子プロセスを生成し、親は子のPIDを`PIDFILE_PATH`に書き込んでから終了する。子は`os.setsid()`で制御端末から切り離し、stdinを`/dev/null`へ、stdout/stderrを`log_path(first_period)`(line-buffering)へリダイレクトする。作業ディレクトリは変更しない(`perNNNN/`や設定ファイルを起動時のカレントディレクトリからの相対パスで解決している既存仕様のため、通常のdaemon実装にある`chdir('/')`はあえて行わない)。
  - `switch_log(period)`: 新しいperiodのログファイルへstdout/stderrを切り替える。`daemonize()`と同じリダイレクト処理(`_redirect_stdio()`)を共有。
  - `install_sigterm_handler()`: SIGTERMを`KeyboardInterrupt`へ変換する。バックグラウンド実行中の`mada.py`に送るSIGTERMが、Ctrl+Cと全く同じ`except KeyboardInterrupt`/`finally`の後片付け経路(regulator監視停止・`run_encoder_power_down`・`run_daq_killer`)を通るようにするため。
  - `write_pidfile()`/`remove_pidfile()`: PIDファイルの書き込み・削除(stale時は無視)。
- `scripts/mada.py`: `-d/--daemon`(バックグラウンド実行)を追加。`main()`は`RunLogger.new_period()`で開始periodを確定してから(ログファイル名の決定に必要なため)`daemonize()`を呼び出す。`install_sigterm_handler()`は`--daemon`指定の有無によらず常時登録する。終了時(`--daemon`時のみ)、正常系・SIGTERM系のどちらの経路でも`finally`でPIDファイルを削除する。`run_daq()`のperiodループは、次のperiodへ進んだ直後(`New period created : perNNNN`を出力する前)に`switch_log()`でログ出力先を切り替える。
- `scripts/mada_stop_daq.py`を新規追加。固定のPIDファイルを読み、プロセスが生きていればSIGTERMを送るだけの薄いスクリプト(オプションなし)。プロセスが既に終了している(stale pidfile)場合は警告を出してPIDファイルを削除する。送信後の終了待ち合わせは行わない(既存の`mada_kill_*`系のfire-and-forgetなスタイルに合わせた)。既存の`mada_daq_killer.py`(MadaIwakiの強制終了+直近.infoの補完を行う復旧用ツール)とは役割を分離しており、`mada.py`本体プロセスを正常系で止めるのは`mada_stop_daq.py`が担う。
- `.gitignore`に`run`を追加。
- `README.md`の「Start DAQ」節に`-d/--daemon`の説明を、新規に「Stop a background DAQ run」節を追記。
- `scripts/mada.py`の`ProgressMonitor.render()`: 従来、非TTY出力時は`poll_interval`(0.2秒)ごとにboard毎のイベント数行を`print()`しており、TTYでは同じ行をANSIエスケープで上書きするだけなのに対し、ログファイルへリダイレクトした場合は延々と行が追記されファイルサイズが際限なく増えていた。`render()`に`final`引数を追加し、非TTY時は取得完了時の最終呼び出し(`final=True`)でのみ出力するように変更。ログには各ファイルにつきboard毎1行、最終的な取得イベント数のみが記録されるようになった。TTY側の表示(その場での上書き)は変更なし。

## 動作確認

- `mada_daemon.py`単体で、`$MADAHOME/run/`の自動作成、fork/setsidによる端末切り離し(親PID=1になること)、`<run_name>_<period>.log`への即時出力、SIGTERM送信で`KeyboardInterrupt`相当の後片付け分岐(PIDファイル削除を含む)に入ることを確認(ハードウェアを使わないダミースクリプトでの検証)。
- `main()`/`run_daq()`のperiodループを再現したダミースクリプトで、`per0000`〜`per0008`まで進む間に9個の`<run_name>_000N.log`が作られ、各ファイルにそのperiod分の出力のみが記録されること、SIGTERM時の停止メッセージがその時点で書き込み中だったperiodのログファイルに正しく入ることを確認。
- `mada_stop_daq.py`で、実行中プロセスへのSIGTERM送信→対象プロセスがPIDファイルを削除して正常終了する一連の流れを確認。
- `ProgressMonitor.render()`について、非TTYを模したスタンドアロンテストで、20回分のポーリングループでは何も出力されず、最終呼び出し(`final=True`)でboard数分(2行)のみが出力されることを確認。
- 実機を用いたDAQ全体でのバックグラウンド実行確認は未実施。
