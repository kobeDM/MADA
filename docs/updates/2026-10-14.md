# LVリセット監視の起動をAP ONの入口で保証

## 背景
- 監視を `mada.py` から独立させた(2026-10-10)ため、監視を起動し忘れたまま `mada.py` を動かすと、過電流が出てもリセットがかからなかった(2026-10-14 09:27 から Module-2 で OVERCURRENT が継続。起動時の警告が端末にしか出ず気付かなかった)。

## 変更
- `run_set_ap(io=1)` が、AP を入れる前に `ensure_autoreset_running()` で監視の起動を保証する。`mada.py`、`mada_encoder_power.py`、`mada_set_ap.py` が共通でこれを通る。`bin/SetAP` の直接実行は対象外。
  - 監視が動いていなければ起動し、別の設定で起動していれば再起動する。
  - 監視自身が AP を戻すときは `ensure=False` で再帰を避ける。
- `mada.py` は `require_monitor=True` で呼ぶため、起動できなければ MonitorError で停止する。DAQ中もファイル境界ごとに確認し、落ちていれば再起動、できなければ安全停止する。単体の `mada_set_ap.py` / `mada_encoder_power.py` は警告のみ。
- 監視は、アクティブな全基板の AP が `--idle-exit` 秒(既定600)連続で OFF のとき自分で終了する。
- 二重起動は `run/mada_autoreset.lock` の排他ロックで防ぐ。PID と設定のパスは、ロック取得後に監視自身が `run/mada_autoreset.pid` / `.config` に書く。
- 起動保証の処理は `scripts/mada_autoreset_ctl.py` に分離(`mada_set_ap.py` との循環 import を避けるため)。`mada_daemon.py` の `detach` はPIDファイル指定を任意にした。

## 検証 (基板・ADALMには触れず、実在しない基板の設定と別のMADAHOMEで実施)
- 起動、すでに起動中なら何もしない、3並列の呼び出しでも1つだけ、別設定での再起動、停止後のロック解放を確認した。
- アイドル終了(AP OFF 2秒で自己終了)、AP ON なら継続、`run_set_ap` の4経路 (io=1 要求あり/警告のみ/io=0/ensure=False) の呼び出し有無を確認した。
- 未確認: 実機の基板での通し運転(稼働中のDAQへの影響を避けたため)。

## 運用上の注意
- 変更前の監視 (PID記録のみ、設定の記録なし) が動いている場合は、次の `ensure` で再起動される。
