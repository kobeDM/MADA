## イベント構造(バイトオフセットは1イベント先頭からの相対値)

| Byte | 内容 |
|---|---|
| 0x000-0x001 | ヘッダ: `0xeb90` |
| 0x002-0x003 | ヘッダ: `0x1964` |
| 0x004-0x007 | Trigger counter(上位/下位16bitずつ、計32bit) |
| 0x008-0x00b | Clock counter(32bit) |
| 0x00c-0x00f | Input Ch2 counter(32bit) |
| 0x010 + 8×clock | FADC Ch0-Ch3(4chぶん、clock深さ分繰り返し) |
| (末尾寄り)0x1016 | version (year) / version (month) |
| 0x1018 | version (sub) / Encoding Clock Depth |
| 0x1020 + 20×hit | 固定ヘッダ的な値(`0x8`, `0x0`等) |
| 0x1022 + 20×hit | Encode clock |
| 0x1024-0x1032 (+20×hit) | hit情報(128ch分、16bitずつ8行でch127-0を表現) |
| Footer | `0x75504943` = ASCII `"uPIC"` |

ヘッダのマジックバイト `eb 90 19 64` は各イベントの先頭4バイト固定。フッタの `75 50 49 43`("uPIC")が各イベントの末尾4バイト固定。

## フィールドとファームウェア信号の対応(Formatter.vhd)

| データフォーマット上のフィールド | VHDL信号 | 備考 |
|---|---|---|
| Trigger counter | `EvtCount` | `Trigger`(main.vhdの`ExDinReg(2)`由来)の立ち上がりでインクリメント |
| Clock counter | `LatchedCnt` | `ClkCount`をTrigger立ち上がり時にラッチした値。`ClkCount`は100μsごとに+1する自走カウンタ(下記参照) |
| Input Ch2 counter | `regGSOcount` | main.vhdの`TrgCounter`をラッチした値。`TrgCounter`は`ExDinReg(3)`(GSOトリガ)の立ち上がりでインクリメントする、Trigger counterとは別系統のカウンタ |
| Encoding Clock Depth | ジェネリック`ClkDepth` | FADC波形サンプル数(1イベントあたりのclock繰り返し数)を規定 |
| hit情報 | `HitData` | 128ch分のヒットビットマップ |

### Clock counterの時間分解能

`Formatter.vhd`内の`cnt100us`プロセスが100MHzクロックで約9993サイクルごとに`clk100us`を1回アサートしており、`ClkCount`はこの立ち上がりで+1される。したがって**Clock counterは1カウント=約100μs**の実時間カウンタとして扱える。

## リセット系統(2種類、どちらもEvtCount/LatchedCnt/regGSOcountを0クリアする)

`Formatter.vhd`: `ECntRst <= RST or CntReset;`

| 信号 | 生成元 | 性質 |
|---|---|---|
| `CntReset` | main.vhd: `ExDinReg(4)`をデバウンス(5サンプル一致) | ADALM経由の外部入力信号。mada.py側の「counter reset」操作(`mada_adalm_control.py`)がこの系統に対応すると考えられる(配線の実機確認は未実施) |
| `RST`(Formatterへの入力、main.vhdでは`SystemRst`) | main.vhd: `SystemRst <= not locked;`(`locked`は`PLLE2_BASE`のLOCKED出力) | PLLロック喪失によるシステム全体リセット。`SystemRst`は`Formatter`以外にも`DAC_set`/`FADC_reg`等、基板内の主要サブモジュール大半のリセットに共通配線されている |

`SysRunning <= not (SystemRst or SiTCP_Reset)`が基板上のLED(`LED_1_OB`)に配線されており、`SystemRst`または`SiTCP_Reset`のアサート状況を目視で確認できる。

## トリガーカウンタの継続性について

Trigger counter(`EvtCount`)は、mada.pyが発行するファイル区切り(1ファイルあたりevent_num件)とは連動してリセットされない。ファイル間で連続した値を取るのが正常な挙動である(2026-08-24の検証で確認)。
