# SCIモードの出力データ仕様(アナライザ向け)

対象読者: SCIモードの出力(`SCI_NNNN.root`)を解析するアナライザの開発者。
ここでは、ファイルの構造と意味、解析で注意すべき点を定める。取得の手順や装置の設定は、MADAのREADMEの「SCI mode」を参照する。

## 1. 何を測るか

PMTのパルスの時刻を、DAQのトリガーの時刻に対する相対値で記録する。
ドリフト時間は、この時間差から求める。TPCのデータ(`.mada`)とは独立に解析できる。

- シンチレーション光が先にPMTに届き、そのあと電子がドリフトして、DAQのトリガーが掛かる。
- したがって、相関のあるPMTパルスは、トリガーより前(時間差が負)に現れる。ドリフト時間は、その絶対値である。
- 記録される時間差には、トリガー生成やケーブル、ディスクリミネータによる固定の遅れが含まれる。ドリフト時間の絶対値を出すには、この遅れを引く必要がある。電場を変えた複数の測定の差を使えば、固定遅れは消える。

## 2. 取得の仕組み(解析に必要な範囲)

- 装置は、DAQ用とは別のADALM2000である。入力1にPMT、入力2にDAQのトリガーを、どちらもNIM信号(約-0.8 V)で、50 Ωで終端して入れる。
- 2チャンネルを、同じクロック(100 MS/s、10 ns間隔)で同時にサンプリングする。時刻は、すべて同じバッファの先頭サンプルを基準にした値である。2チャンネル間の基準のずれはない。
- ADALMは、入力2(DAQのトリガー)の立ち下がりエッジ(閾値 -0.4 V)でハードウェアトリガーを掛ける。トリガーの前の8000サンプル(80 us)と、後ろの約192サンプル(約2 us)を含む、8192サンプル(約82 us)のバッファを1つ取り込む。トリガーのエッジは、バッファの8000番目のサンプル付近に来る。
- ソフトウェアで、トリガー側のバッファからトリガーのエッジを、PMT側のバッファからすべてのPMTパルスを、閾値(既定はどちらも -0.4 V、立ち下がり)の通過として探す。通過時刻は、前後の2サンプルの直線補間で求めるので、10 nsより細かい値になる。
- 1回のトリガーにつき1回、バッファを取り込む。バッファの読み出し中のトリガーは取れない。

## 3. ファイル

1ファイル(DAQの1ファイル)ごとに、ピリオドのディレクトリ(`perNNNN/`)へ、次のファイルが作られる。`NNNN`は、DAQのファイル番号(`GBKB-xx_NNNN.mada`の番号)と同じである。

| ファイル | 内容 |
|---|---|
| `SCI_NNNN.root` | トリガーごとの記録(下記)。 |
| `SCI_NNNN.info` | ファイルの要約(下記)。取得の終了時に書かれる。 |
| `SCI_NNNN.status` | 取得中の進捗(`triggers`、`last_epoch`、`time`)。取得中だけ意味がある。解析では使わない。 |

DAQがファイルのやり直しをして、無効になったファイルは、DAQ側の`.info`に`valid: false`が入る。そのファイルの番号に対応する`SCI_NNNN.root`も、解析から除くこと。

### 3.1 `SCI_NNNN.root`

オブジェクトは、次の2つである。

- `meta`(`TNamed`): 取得時の設定。`title`が、`key=value`を`;`で区切った文字列である。キーは、`serial`、`pmt_channel`、`pmt_threshold_V`、`pmt_edge`、`trigger_channel`、`trigger_threshold_V`、`trigger_edge`、`range`、`buffer_samples`、`pre_trigger_samples`、`sample_rate_Hz`、`start_epoch`である。時間軸の換算(サンプル間隔、バッファ長、トリガー位置)に、この値を使うこと。値をコードに固定で書かない。
- `trigger`(`TTree`): 1トリガーにつき1エントリー。

`trigger`のブランチは、次のとおり。

| ブランチ | 型 | 単位 | 内容 |
|---|---|---|---|
| `seq` | int | - | ファイル内の通し番号(0から)。 |
| `t_epoch` | double | s(UNIX時刻) | そのバッファを読み出した時刻。PCの時計による。DAQのファイルの時刻と、おおまかに対応する。 |
| `trig_ns` | float | ns | トリガーのエッジの時刻(バッファ先頭から)。ハードウェアトリガーの位置(約 `pre_trigger_samples` x 10 ns)の近くになる。 |
| `n_pmt` | int | - | そのトリガーで見つかったPMTパルスの数。 |
| `pmt_dt` | vector<float> | ns | パルスごとの時間差(PMTの時刻 - トリガーの時刻)。負は、トリガーより前。 |
| `pmt_amp` | vector<float> | V | パルスの最も深い電圧(負の値)。 |
| `pmt_width` | vector<float> | ns | パルスが閾値を越えていた時間。バッファの終端で切れたパルスは -1。 |
| `flags` | int | - | ビットフラグ(下記)。 |
| `wave_pmt`, `wave_trig` | vector<float> | V | 波形(各8192サンプル)。取得時に `save_waveform` を1にしたときだけ存在する。 |

`flags`のビットは、次のとおり。

- 1: トリガーのエッジが、期待する位置(8000サンプル目)の前後200 ns以内に見つからなかった。`trig_ns`は0、`n_pmt`は0で、`pmt_dt`は空である。そのエントリーは、解析に使わない。
- 2: PMTまたはトリガーのバッファに、レンジの98 %以上に達したサンプルがある(飽和)。パルスの波高と幅は、信頼できない。時刻は使える場合が多いが、扱いは解析で決めること。

解析に使うエントリーは、原則として`flags==0`である。

### 3.2 `SCI_NNNN.info`

`start`、`end`(UNIX時刻)、`triggers`(記録したトリガー数)、`pmt_pulses`(記録したPMTパルスの総数)、`reason`(終了の理由。通常は`stopped`)と、`meta`と同じ設定の文字列が入る。

## 4. 解析上の注意

1. **時間軸の換算:** サンプル間隔は`1e9 / sample_rate_Hz`(ns)で、現在は10 nsである。時間差の分布をクロック単位で見るなら、10 nsで割る。バッファ全体は、トリガーの82 us前から、約2 us後までである。
2. **偶然の重なり:** バッファが長いので、トリガーと無関係なPMTパルスが、バッファ全体に一様に入る。トリガーより十分前(例えば、-8000 nsより前)の平均が、偶然の重なりのレベルである。ドリフトによる相関は、このレベルの上に出るピークとして見る。
3. **統計:** 252Cfの現在の条件では、PMTのパルスを伴うトリガーは約1 %で、数ファイル(約2000トリガー/ファイル)で、数十パルスである。ドリフト時間の評価には、数十ファイル以上を足し合わせる必要がある。
4. **取りこぼし:** SCIのトリガー数は、DAQのイベント数(2000)より、約5〜6 %少ない。原因は未確認である。SCIのトリガーとTPCのイベントを1対1で対応させる用途には、使えない。独立した解析として使うこと。
5. **パルス検出の限界:**
   - バッファの先頭のサンプルですでに閾値を越えていたパルスは、通過時刻が決まらないので、記録されない。
   - 閾値を越えたあと、2サンプル以内のすき間は、1つのパルスとして扱う。これより長いすき間があると、別のパルスになる。
   - ADALMの入力の帯域は約25 MHzである。パルス幅が約20 nsより短いと、波高が下がる。時刻は、立ち下がりの通過だけを使うので、影響は小さい。
6. **波形:** 閾値やパルス幅の判定を、後から変えたい場合は、取得時に`save_waveform`を1にする必要がある(ファイルが大きくなる)。現在のデータには、波形が無い。

## 5. 解析マクロ

DAQのリポジトリにあった`rootmacro/SciDt.cxx`(`pmt_dt`の分布と偶然の重なりのレベル)は、アナライザへ移したため、削除した。解析の詳細は、アナライザ側で定める。

## 6. アナライザへ渡すもの

- 各ピリオドの`SCI_NNNN.root`と`SCI_NNNN.info`
- この仕様書

パルスの検出(`include/SciPulse.h`、`source/AdalmAnalogIn.cc`)は、DAQ側に残す。アナライザは、`pmt_dt`をそのまま使えばよい。
